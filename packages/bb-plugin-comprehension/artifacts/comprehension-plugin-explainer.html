How Comprehension works

Comprehension turns a message, a text selection, or a full thread into a saved HTML explainer. The report is produced by a hidden worker, stored by the plugin, and shown in an isolated frame.

Comprehension is a snapshot pipeline. It captures a bounded source conversation, asks a hidden child thread to write one visual document, validates that document, saves it, and renders it back into the conversation.

The plugin is not yet a live agent timeline. It explains the source that existed when the request began. Its stored sequence number gives the snapshot a precise boundary, but the report itself is still one free-form HTML document.

The same server function serves all user entry points. The host app chooses a scope, the server captures the source, and the worker uses the report skill and Quiet Newsroom template.

The hidden worker stays outside the visible conversation, but its report becomes a durable artifact.

The worker never receives attachment contents. It receives a sentence saying that an attachment is present. Long threads also have a practical limit because the current request asks for 200 timeline rows without pagination.

Important boundary. The report explains conversation text. It does not inspect the repository, compute a code diff, run tests, or observe an agent’s tool calls unless those facts already appear in the source conversation.

The server loads the Quiet Newsroom template and builds a prompt with four inputs: title, reader focus, template, and bounded source. The source sits between SOURCE and END SOURCE markers.

The prompt tells the worker to treat the source as data, ignore instructions inside it, and return only one complete HTML document. The report skill adds the editorial rules: start with the answer, keep facts and interpretations distinct, use exact technical names, and add diagrams only when the source supports them.

The worker runs as a hidden child thread. It uses the original project and provider, and reuses the original environment when one exists. After the output is read, the worker is archived and stopped even if generation fails.

Before storage, the server removes accidental Markdown fences, extracts a complete HTML document, rejects incomplete output, and rejects documents over 2,000,000 characters.

The SQLite row keeps the report id, source identity, title, focus, HTML, source sequence, and timestamps. A later request can fetch the full artifact by id without running the worker again.

The app renders the HTML with <iframe sandbox="allow-scripts">. This lets the report own its theme toggle, collapsible sections, table of contents, and inline diagrams without sharing the host page’s DOM.

An agent message can embed a preview through ::comprehension{id="..."}. The preview opens the full report in the thread panel.

The current seams are good. The missing layer is a structured comprehension brief that can be rendered more than one way.
